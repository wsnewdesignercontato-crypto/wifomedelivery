# Account controls and courier offer card — 2026-10-19

The courier offer keeps a centered, width-limited mobile dialog, compact map, clear earnings and route sections, vertical-only content scrolling, and persistent accept/reject buttons. RideOfferCard is a presentation component; location, ringing, first-accept transaction and payment status remain in the operational NewRideOffer wrapper. The admin-only /admin/previa-corrida page previews fictional data without sending orders, notifications, payments or acceptance commands.

Admin > Usuários uses responsive cards with block/unblock and delete-account actions. Delete requires typing the current email; server authorization is repeated on every request, self actions are denied, and block/delete are denied for accounts holding the admin role. Existing last-admin removal checks remain. The action records an audit intent before mutation and completion afterward. API failures do not produce success toasts.

Deletion uses Supabase Auth deleteUser(id,true), which irreversibly removes login identifiers while retaining the Auth row and existing application history. This is account/login deletion, not erasure of historical orders, financial records or profile references. No DELETE is issued against business tables. Blocking/unblocking uses updateUserById with a documented ban_duration, and restores the same login when unblocked.

Auth banned_until/deleted_at is the single source for account access. A SECURITY DEFINER helper in private reads only the current uid. Restrictive policies are added alongside existing policies on all current public RLS tables and storage.objects. The Data API pre-request hook rejects blocked/deleted users before SECURITY DEFINER RPCs execute; its installation refuses to replace an unrelated hook. Anonymous public access and service-role operations retain their existing rules. Server middleware also checks account access after JWT signature verification. Existing issued JWTs therefore cannot bypass blocking in these paths. Existing signed Storage download URLs remain valid until their original expiration.

Future RLS tables should include account_must_be_active, especially when used by Realtime or Storage (which do not execute the Data API pre-request hook). The hook remains enforced for Data API requests to future tables/RPCs.

Verification: account-control SQL fixtures run with ordinary user claims and BEGIN/ROLLBACK and cover active, banned, unblocked and deleted identities, unchanged historical profiles, anonymous access and admin listing. Full-schema checkout/delivery and customer/courier registration regressions also passed after installation. Security advisors reported no new findings. Auth mutation tests use injected mocks only; no real user's account was blocked or deleted. UI authorization tests reject non-admin actions before privileged imports/mutations. Existing acceptance/ringtone/payment tests remain in the full suite.
